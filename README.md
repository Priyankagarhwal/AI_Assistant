# 🧠 KnowledgeHub AI

A full-stack **Retrieval-Augmented Generation (RAG)** app: upload PDFs into workspaces and ask questions about them. Answers are generated by **Llama 3.3 70B (via Groq)** using only retrieved passages, with **numbered citations down to the file and page**.

---

## ✨ Features

- 📁 **Workspaces** — documents and chat history are isolated per workspace (metadata-filtered retrieval)
- 📄 **PDF ingestion** — text extraction with pypdf, **per-page OCR fallback** (Tesseract) for scanned pages
- 🔍 **Grounded answers with citations** — every answer cites passages as `[1]`, `[2]`, each mapped to `file, page`
- 🚫 **Relevance threshold** — chunks below a cosine-similarity cutoff are dropped; if nothing relevant is found the app says so instead of guessing
- 💬 **Follow-up questions** — recent turns are used to rewrite a follow-up ("what are *its* limitations?") into a standalone query before retrieval
- 📝 **Workspace summary** — map-reduce summarisation over *every* chunk, so large workspaces don't overflow the LLM context window
- 🧹 **Consistent deletes** — deleting a document or workspace removes its SQLite rows, Chroma vectors **and** stored PDF
- 🛡️ **Safe uploads** — PDF signature check, size limit, server-generated file names (no path traversal / overwrites)
- ✅ **Tests** — pytest suite that runs offline (fake embedder + fake LLM)

## 🏗️ Architecture

```
            ┌──────────── React + Tailwind (Vite) ────────────┐
            │ Workspaces · Upload · Chat · History · Summary  │
            └───────────────────────┬─────────────────────────┘
                                    │ REST (Axios)
┌───────────────────────────────────▼───────────────────────────────────┐
│ FastAPI                                                               │
│                                                                       │
│  Upload:  PDF ─► pypdf (OCR fallback per page) ─► split per page      │
│           (1000 chars, 200 overlap) ─► MiniLM-L6-v2 embeddings        │
│           ─► ChromaDB (cosine) with {workspace_id, document_id, page} │
│                                                                       │
│  Chat:    question + last turns ─► rewrite to standalone query (LLM)  │
│           ─► top-k search filtered by workspace ─► drop low scores    │
│           ─► Llama 3.3 70B (Groq) with numbered context ─► answer [n] │
│                                                                       │
│  SQLite (SQLAlchemy): workspaces · documents · chat_history           │
└───────────────────────────────────────────────────────────────────────┘
```

## 🚀 Getting Started

### Prerequisites
- Python 3.10+ and Node.js 20+
- A free [Groq API key](https://console.groq.com)
- *(Optional, for scanned PDFs)* [Tesseract OCR](https://github.com/UB-Mannheim/tesseract/wiki) and [Poppler](https://github.com/oschwartz10612/poppler-windows/releases). Put them on `PATH` or set `TESSERACT_CMD` / `POPPLER_PATH` in `.env`.

### Backend
```bash
cd backend
python -m venv venv
venv\Scripts\activate            # Windows  (source venv/bin/activate on macOS/Linux)
pip install -r requirements.txt
copy .env.example .env           # then set GROQ_API_KEY   (cp on macOS/Linux)
uvicorn app.main:app --reload
```
API: `http://127.0.0.1:8000` · interactive docs: `http://127.0.0.1:8000/docs`

### Frontend
```bash
cd frontend
npm install
npm run dev                      # http://localhost:5173
```
Set `VITE_API_URL` in `frontend/.env` if the backend is not on `http://127.0.0.1:8000`.

### Tests
```bash
cd backend
pytest -q
```

## 📡 API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/health` | Health check |
| GET | `/workspace/` | List workspaces |
| POST | `/workspace/` | Create workspace `{name, description}` |
| DELETE | `/workspace/{workspace_id}` | Delete workspace + its documents, vectors, chats |
| POST | `/upload/pdf` | Upload a PDF (multipart: `workspace_id`, `file`) |
| GET | `/documents/{workspace_id}` | List documents in a workspace |
| DELETE | `/documents/{document_id}` | Delete a document + its vectors and file |
| POST | `/chat/` | Ask `{workspace_id, question, history?}` → `{answer, sources[]}` |
| GET | `/chat/history/{workspace_id}` | Chat history |
| DELETE | `/chat/{chat_id}` | Delete one chat entry |
| POST | `/summary/` | Summarise a workspace `{workspace_id}` |
| GET | `/dashboard/` | Counts of workspaces, documents, chats |

Errors use standard HTTP status codes (`404` not found, `413` too large, `415` not a PDF, `422` no extractable text, `502/503` LLM unavailable) with a `detail` message.

## 📏 Evaluating retrieval

`backend/eval/eval_retrieval.py` measures **Hit@k** and **MRR** on a hand-labelled question set (question → file + page that contains the answer), and how many unanswerable questions are correctly rejected by `MIN_RELEVANCE_SCORE`. It makes no LLM calls.

```bash
cd backend
python -m eval.eval_retrieval eval/questions.example.json
```

Use it to tune `CHUNK_SIZE`, `CHUNK_OVERLAP`, `RETRIEVAL_K` and `MIN_RELEVANCE_SCORE`.
After changing chunking or the embedding model, rebuild the index with `python -m scripts.reindex`.

## ⚠️ Known limitations

- No authentication — intended for local / single-user use.
- Ingestion runs inside the upload request; very large PDFs (or OCR-heavy ones) take a while. A background job queue would be the next step.
- OCR quality depends on scan quality; handwriting is poorly supported.
- Only PDF input is supported.
